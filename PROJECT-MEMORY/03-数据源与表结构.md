# 03 · 数据源与表结构

## 当前结构化数据主源

销量主链路使用懂车帝公开 JSON 接口：

```text
GET https://www.dongchedi.com/motor/pc/car/rank_data
```

核心参数：

| 参数 | 含义 |
|---|---|
| `rank_data_type=11` | 销量榜 |
| `new_energy_type=1/2/3` | 纯电 / 插混 / 增程 |
| `month=YYYYMM` | 月份 |
| `count / offset` | 分页 |

返回字段覆盖品牌、车系、销量、当期/上期排名、指导价、经销商价、口碑数等。

## 当前采集策略

权威脚本是 `data/crawl_sales.py`。它使用 Python 标准库 HTTP，不依赖浏览器或额外抓取框架：

1. 默认从 `202401` 到上一个完整自然月；
2. 读取已有 JSONL，识别缺失的“月份 × 能源类型”分区；
3. 缺失分区补采，最近两个完整月无条件刷新；
4. 对每个分区分页请求，带超时、有限重试和节流；
5. 校验响应 `sells_rank_month`，拒绝把最近已发布月静默冒充为请求月；
6. 以 `(_month, _new_energy_type, series_id)` 去重；
7. 临时文件完成后原子替换 `data/raw/sales_rank_raw.jsonl`。

这使重复运行具备幂等性，并允许榜单后续修订被最近两月刷新覆盖。

早期“销量主链路必须使用浏览器抓取专用环境”的说明已经废止。`data/crawl_koubei.py` 属于可选的历史/人工补充脚本，不参与当前生产自动补数主链路，部署与基础演示不能依赖它。

## 两类初始化数据必须区分

### 零网络合成样例

```bash
python seed_real.py
```

`seed_real.py` 生成确定性的本地演示库，用来验证 schema、Text2SQL、图表和 UI。它的车型名称接近真实世界，但销量、价格等数值是**合成样例**：

- 不能作为业务结论；
- 不能写成爬取的数据量；
- 不能用于简历中的真实准确率或市场分析。

### 真实公开数据

```bash
python data/crawl_sales.py
python data/clean_load.py
```

`crawl_sales.py` 获取公开 JSON，`clean_load.py` 进行字段转换、空值处理、去重并写入分析库。公开材料若引用真实市场数字，必须说明采集日期、来源和口径。

截至 2026-07-29，当前真实快照覆盖 `202401–202606`、8402 条销量事实；
2026-05 为 337 条，2026-06 为 331 条，2026-07 为 0 条。7 月请求返回的
331 行仍声明最新发布月为 `202606`，属于源站静默回退，已被 guard 拒绝。

## 分析库 schema

权威定义：

- 设计参考：`sql/schema.sql`
- 本地实际建库：`data/clean_load.py`
- 生产初始化：`deploy/postgres/initdb/sql/10-bi-analysis.sql`

### 维度表

| 表 | 粒度与主要字段 |
|---|---|
| `dim_brand` | 品牌；`brand_id, brand_name, sub_brand_id, sub_brand_name, country_type, is_new_force` |
| `dim_series` | 车系；`series_id, series_name, brand_id, segment, powertrain, endurance_km, guide_price_min/max, image_url` |
| `dim_date` | 月；`date_id, year, month, quarter, ym` |

`dim_date.date_id` 固定使用 `YYYYMM` 整数，例如 `202505`。它不是 1、2、3 的顺序 ID。

### 事实表

| 表 | 粒度 | 核心字段 |
|---|---|---|
| `fact_sales_rank` | 车系 × 月 × 能源类型 × 榜单类型 | `rank, last_rank, volume` 与来源血缘 |
| `fact_price` | 车系 × 价格快照 | 指导价、经销商价、降价信息与来源血缘 |
| `fact_review` | 车系 × 口碑快照 | 口碑数、可选评分/情感与来源血缘 |

销量幂等键：

```text
UNIQUE(series_id, date_id, new_energy_type, rank_type)
```

`volume` 来自接口的 `count`。`last_rank` 缺失或 0 表示无可比较的上期排名，应清洗为 NULL。`powertrain` 由 `new_energy_type` 映射为纯电、插混或增程。

榜单是全国口径，当前没有可靠地区维度，因此故意不创建空的 `dim_region`。

## 应用库与 RAG schema

权威实现：

- ORM：`app/models.py`
- PG RAG：`app/rag/pg.py`
- 参考 schema：`sql/schema_app.sql`
- 生产首启：`deploy/postgres/initdb/sql/30-app-schema.sql`

主要表：

| 表 | 用途与隔离 |
|---|---|
| `users` | 账号、角色、禁用状态、`token_version`；生产注册由配置门禁控制 |
| `conversation / message` | 会话、消息、SQL 审计、图表/引用元数据 |
| `kb_document` | 文档；`user_id IS NULL` 为公共文档，否则为私有文档 |
| `kb_chunk` | 父子块、关键词 tokens、1024 维 embedding、模型版本与维度血缘 |
| `user_profile / memory_episode` | 用户偏好和会话摘要 |
| `saved_insight / shared_insight` | 收藏与受控分享 |

`kb_chunk` 的关键字段：

```text
level / parent_chunk_id / is_retrievable / chunk_type
heading_path / content / content_embed / content_tokens
embedding / embedding_model_version / embedding_dim
page_no / token_count / user_id
```

子块 `is_retrievable=true` 并可存 embedding；父块提供生成上下文。向量召回只读取当前模型版本、维度和 BLOB 长度兼容的子块；旧向量仍可参与关键词召回。所有在线召回必须在检索前按公共文档或当前 `user_id` 过滤，不能召回后再依赖前端隐藏。

问答日配额不单独维护计数表。请求被系统接受时，在模型执行前原子写入 user message 并统计 UTC 自然日用量；生产模板默认每账号 30 次。断连/上游失败仍占已接受额度，但不写虚假的 assistant message。

## RAG 数据路径

### 本地

```text
文件 → lite parser → 父子分块 → BGE embedding
     → SQLite 文档/chunk + numpy 向量文件
```

本地同步入库，面向小语料和可复现演示。

### 生产配置

```text
上传原文 → MinIO
        → Redis/Celery
        → lite parser → 父子分块 → BGE embedding
        → PostgreSQL + pgvector
```

当前 `PARSER_BACKEND=lite`。MinerU 只是预留接口，未完成集成。

## 无数据采集结果写到哪里

查询无结果触发的 `Research → Plan → Code ≤3 → Review` 任务，仅在
`should_write_to_rag=true` 时写入**发起用户的私有 RAG**。

它不会：

- 写入 `fact_sales_rank`、`fact_price` 或 `fact_review`；
- 修改公共知识库；
- 自动重跑原 SQL。

结构化事实更新仍由受控的 `crawl_sales.py → clean_load/load_analysis_pg` 链路完成。
