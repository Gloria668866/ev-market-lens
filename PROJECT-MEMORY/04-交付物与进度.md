最后校准：**2026-07-29**

## 当前结论

车市镜已经具备一个秋招作品项目应有的主链路和工程深度：

- 13 节点、五意图 LangGraph；
- Text2SQL 的安全、执行重试和语义正确性校验；
- 父子块混合检索 RAG、reranker、证据门控和引用；
- 无数据后的异步多 Agent 研究链；
- JWT 多租户、SSE、Vue/ECharts 产品前端；
- 自动化测试、四类评测、健康检查和生产部署配置。

本地证据已经覆盖固定回归集、真实公开销量快照和 64/64 活动向量血缘，
但当前还不能宣称“已生产验证”。最大缺口是：在真实云服务器的全新数据卷上
完成一次完整部署验收，并把最终在线地址、演示账号和验证记录补回文档。

## 已完成

### 1. 产品主链路

- 五类意图：`sql / rag / hybrid / clarify / chat`；
- 13 个 LangGraph 节点；
- SQL 失败修复环；
- hybrid 双分支并行与 `compose(defer=True)`；
- SSE 返回意图、数据、图表、洞察、引用和任务进度；
- 多轮上下文只对代词/省略追问继承实体。

### 2. Text2SQL

- Schema Linking 与领域 prompt；
- `sqlglot` AST 只读护栏；
- 只读执行、最多两次修复；
- 确定性结构护栏 fail-closed；
- 可选 LLM 语义校验器异常 fail-open；
- 图表合同固定为：

```text
default_type / applicable_types / dimension / measures / title
```

- `date_id` 已统一为 `YYYYMM`；
- 固定 60 题 Gold SQL 可执行和执行结果回归已通过。

### 3. RAG

- `lite` 文档解析；
- 结构感知父子分块；
- BGE-large-zh embedding；
- 向量 + jieba 关键词召回和 RRF；
- BGE reranker；
- Top child 证据充足性门控；
- 通过门控后父块去重、相邻合并、预算裁剪和冲突并列；
- Pydantic 校验生成 JSON，答案 `[来源 N]` 与 `used_sources` 必须严格一致；
- typed 引用包含 `source_no / doc_id / page_no / chunk_id`；
- reranker 不可用时要求向量/关键词双路证据；
- 子块记录 embedding 模型版本与维度，向量检索只读取兼容空间；
- SQLite 旧库自动迁移，PG 通过启动前 migration 补列；
- `data/reindex_embeddings.py` 可只重建缺失/旧版/错维度向量；
- 公共文档与用户私有文档隔离；
- 本地 SQLite + numpy 和生产 PG + pgvector 两套后端。

2026-07-29 本地活动子块已真实重建为 64/64 compatible，
legacy/mismatched/missing 均为 0。这个结果只代表当前本地知识库，不代表生产 PG。

MinerU 未接入，不能列为完成项。

### 4. 无数据研究任务

当前 DAG：

```text
Research → Plan → Code agents（最多 3 并行）→ Review
```

- 请求线程不执行重型 pipeline；
- 生产进入 Redis/Celery；
- 本地无队列时走单 worker，并限制运行中与等待中任务总数，满载快速拒绝；
- Code Agent 只调用预定义工具；
- `search_web` 按 Tavily → Brave → 百度/Bing HTML 降级并统一结果 schema；
- 本地可使用 HTML 降级，生产至少一个官方搜索 key 才通过 readiness；
- 审核结果写入发起用户私有 RAG。

尚未实现：

- 自动回写销量事实表；
- 自动重跑原 SQL；
- 自动发布为全局公共知识。

### 5. 数据与初始化

- `data/crawl_sales.py` 使用公开 JSON API + Python 标准库 HTTP；
- 默认幂等补齐缺失分区并刷新最近两个完整月；
- `data/clean_load.py` 构建本地星型模型；
- `seed_real.py` 提供零网络合成样例；
- 合成样例和真实采集数据的口径已经在公开文档分开。

截至 2026-07-29，真实公开快照覆盖 `202401–202606`、8402 条销量事实；
2026-05 为 337 条，2026-06 为 331 条。源站尚未发布 2026-07，返回的
331 条实际仍标记 `202606`，已被发布月 guard 拒绝，7 月保持 0 条。生产定时任务
在每月 8 日和 15 日 03:00 重试，不能把源站静默回退伪装成新月份。

### 6. 工程化

- JWT、多租户数据隔离、密码变更 token 失效；
- `APP_ENV=production` 默认关闭公开注册，显式开启才允许匿名创建账号；
- 问题被接受时原子写入 user message 并占用账号级 UTC 自然日配额，生产模板默认 30 次；
- 断连或模型失败不退已接受额度，也不写虚假的 assistant message；
- `/api/ask`、`/api/ask_sync`、`/api/kb/ask` 共享每 API 进程有界容量，
  满载在模型调用和配额占用前返回 503；
- 流式问答、同步问答、知识库问答和任务进度 SSE 均使用短 DB Session，
  不在模型或最长 15 分钟的流生命周期持有连接；
- 会话、消息、图表、引用、收藏和分享；
- BGE 权重结构检查和 `/health?deep=true` 实际推理检查，`/ready` 同时检查向量血缘；
- 管理员可读取当前 API 进程的 LLM 调用、错误、token、延迟分位数和估算成本；
  指标重启清零且不跨进程聚合，不能表述为全局监控；
- Windows 一键启停与 PID 校验；
- pytest、前端 build、CI 评测门禁；
- Docker Compose、Caddy HTTPS、PG/pgvector、Redis、MinIO、Celery worker/beat；
- 数据初始化、应用库幂等 migration、向量重建、模型下载、备份和恢复脚本。

## 当前评测口径

| 评测 | 当前可复现结果 | 不能推出的结论 |
|---|---|---|
| Text2SQL | 固定 60 题执行结果回归 60/60；首轮与重试明细见提交报告 | 未知问题 100% 泛化 |
| Intent | 110 条五分类固定回归集 110/110；固定集全部走确定性规则，0 次 LLM 调用；延迟分位见提交报告 | 把常见路由防回归当作线上泛化率，或声称它衡量了新问题的 LLM 兜底准确率 |
| RAG 正样本 | 本地 SQLite + numpy：13/13 严格通过；claim 来源有效率、归并上下文支持率、关键锚点支持率均为 100% | 最终答案 faithfulness/correctness；生产 PG 准确率 |
| RAG 负样本 | 本地 SQLite + numpy：7/7 证据不足时拒答 | 开放域零幻觉；生产 PG 拒答率 |
| 数据质量 | 以 `eval/reports/data_quality.json` 为准 | 线上源数据永不漂移 |

当前 RAG 评测只有 13 条正样本和 7 条负样本，运行在本地
SQLite + numpy 后端，是检索、证据覆盖和拒答回归门禁，不是生成答案评测或生产统计。
旧的 60 题 RAG LLM-judge、旧 Text2SQL 百分比或旧知识库规模若出现在历史文档中，
只能视作历史实验，不能用于当前 README、简历或面试回答。

测试数量不在文档写死。标准复现命令：

## 2026-07 稳定性收口

已完成的关键修复：

- 修复损坏的 BGE embedding 权重并补齐 reranker，deep health 改为真实推理；
- 修正 `date_id=YYYYMM`、Top-N、时间、价格上下界、能源类型、复合品牌和按月趋势等 Text2SQL 口径；
- 结构护栏在重试耗尽后仍 fail-closed；
- 阻止完整新问题继承上一轮品牌条件；
- RAG 主聊天和知识库问答共用证据门控；
- reranker 降级不再直接沿用 RRF 分数强答；
- RAG 生成结果改为 Pydantic 严格校验，引用编号和实际使用来源不一致时 fail-closed；
- embedding 增加模型版本/维度血缘、旧库迁移、兼容性 readiness 和增量重建；
- 缺数 pipeline 改成异步，任务进度和结果绑定发起用户；
- 问答配额改为接受时原子预占，三个问答入口共享容量并缩短 DB Session 生命周期；
- 未发布月份增加真实发布月校验，5/6 月刷新后阻止 7 月静默回退污染；
- 品牌、车系与 schema 增加 TTL 快照，避免每问重复扫描且不截断当前 433 个车系；
- 增加管理员进程级 LLM 调用、错误、token、延迟分位数和成本指标；
- 修复前端 mock 判断、Markdown、分页、流取消、知识库公共/私有展示和任务进度；
- README、技术设计和 PROJECT-MEMORY 改为以当前代码为准的单一口径。
