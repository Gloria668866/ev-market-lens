# 02 · 当前技术栈与取舍

> 本页只记录当前代码实际使用或已经配置的能力。早期方案里的浏览器型主采集、锁定单一模型、重型解析器已接入、直接使用第三方评测框架等说法均已废止。

## 技术栈

| 层 | 当前选型 | 原因与边界 |
|---|---|---|
| 主数据采集 | Python 标准库 `urllib` + 懂车帝公开销量 JSON API | 不需要浏览器；依赖少；支持超时、重试、幂等补缺和最近两月刷新 |
| ETL | Python + SQLAlchemy/SQLite/PG loader | 清洗规则透明，星型模型可在本地和生产复用 |
| 对话模型 | OpenAI-compatible provider，通过环境变量配置 | 不锁定单一厂商或不存在的模型名；prompt/评测必须在换模型后重跑 |
| Agent 编排 | LangGraph | 显式 State、条件边、重试环、并行 fan-out、deferred join 和 trace |
| SQL 生成与护栏 | 自定义 prompt + `sqlglot` | AST 级只读检查比正则可靠；再叠加业务结构校验 |
| Embedding | BGE-large-zh，本地权重，1024 维 | 中文语义召回；chunk 记录模型版本/维度，旧向量需重建 |
| Reranker | BGE reranker，本地权重 | 提升候选排序；缺失时进入双路证据降级，不直接沿用 RRF 强答 |
| 本地 RAG | SQLite + numpy + jieba | 零基础设施、小语料同步入库和调试 |
| 生产 RAG | PostgreSQL + pgvector + jieba tokens | 持久化、多用户和更大语料检索 |
| 原文存储 | 本地文件（开发）/ MinIO（生产） | 生产保留可重放原文，不把大文件塞业务表 |
| 文档解析 | `PARSER_BACKEND=lite` | 当前支持轻量 PDF/文本解析；MinerU 仅为未来接口预留 |
| 队列 | Redis + Celery | 生产异步文档入库、缺数研究任务和定时刷新 |
| 后端 | FastAPI + POST-SSE | 流式返回 Agent 过程与结果，接口自带 OpenAPI |
| 前端 | Vue 3 + Vite + ECharts | 图表描述符驱动，本地换图，不重复调用模型 |
| 身份与隔离 | JWT + `user_id` + 原子配额 + 有界容量 | 会话、文档、任务隔离；生产关注册；三个问答入口共享并发门禁 |
| 部署 | Docker Compose + Caddy | 单机作品集部署；HTTPS、PG、Redis、MinIO、worker/beat 和备份脚本 |
| 测试与评测 | pytest + 项目内评测脚本 + GitHub Actions | Text2SQL 执行等价、意图混淆矩阵、RAG 检索/拒答、数据质量断言 |

## 关键取舍

### 对话模型可替换，Embedding 不混用

对话模型通过 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 配置，可接不同 OpenAI-compatible provider。换模型后必须重跑意图和 Text2SQL 评测。

Embedding 始终使用专门的 BGE 模型，不能拿对话模型“顺便向量化”。每个子块持久化稳定模型版本和维度；检索只读取当前向量空间。Embedding 模型或版本变化后，用 `data/reindex_embeddings.py` 重建，不给旧向量猜版本。

### 本地零门槛，生产不假装同一规模

本地使用 SQLite + numpy 是为了让面试演示和调试不依赖 Docker。生产配置使用 PG + pgvector、MinIO、Redis + Celery。两套后端共享分块与检索语义，但性能、持久性和并发能力不同，文档必须明确区分。

### 当前使用 lite parser

`app/rag/parse.py` 的默认值是 `PARSER_BACKEND=lite`。MinerU 需要额外模型、资源和集成验收，目前调用会明确提示尚未实现。它只能出现在 backlog，不能出现在“已交付技术栈”里。

### 混合召回不是“向量分 + 关键词分直接相加”

向量与关键词候选先用 RRF 按名次融合，再由 reranker 排序。reranker 不可用时要求向量/关键词双路证据一致，避免把不可比较的分数阈值当成可靠相关性。

### 双层 SQL 校验使用不同故障策略

- AST 安全与确定性结构护栏：fail-closed；
- 可选 LLM 语义校验器自身异常：fail-open。

前者控制安全/确定性错误，后者只是增强层，不能成为可用性单点。

### 不上 Hadoop 或独立大向量集群

当前数据与流量远低于大数据基础设施的收益门槛。单机 PG/pgvector 足以展示工程能力；未来只有在真实容量、吞吐和延迟指标证明瓶颈后才引入新组件。

### 评测方法不冒充第三方框架

当前评测脚本借鉴通用指标思想，但由项目内代码实现。公开材料只说实际运行的方法：

- Text2SQL：Gold 与预测 SQL 的执行结果等价；
- 意图：混淆矩阵与 per-class P/R/F1；
- RAG：目标文档召回、原子 claim 的来源/检索证据覆盖和负样本拒答；
- 数据质量：确定性表级/字段级断言。

不写“已直接接入某第三方评测框架”，因为当前代码没有这一事实。

### 公开 Demo 先控制身份与成本

`APP_ENV=production` 时 `ALLOW_PUBLIC_REGISTRATION` 默认是 `false`，管理员先创建演示账号。问题在模型运行前原子持久化并占用 UTC 自然日额度，生产模板默认 `DAILY_QUESTION_LIMIT=30`；断连/失败不退款但也不伪造回答。`/api/ask`、`/api/ask_sync`、`/api/kb/ask` 共用每进程 `ASK_MAX_CONCURRENCY`。需要开放注册时必须显式配置，并结合模型预算调整门禁。

## 已废止方案

- 浏览器型采集作为销量主链路：公开 JSON API 用标准库 HTTP 更轻、更稳定。
- 锁死任何单一模型：改为 provider configurable。
- MinerU 已完成：改为 lite 已完成、MinerU 预留。
- 本地直接模拟生产规模：明确本地/生产两套实现的用途。
- 测试数量写死在文档：以 pytest 和 CI 当前运行结果为准。
