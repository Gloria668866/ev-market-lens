# 口碑评分 / 车系详情 字段清单（补采探针实测）

> 生成日期：2026-05-25　|　工具：scrapling 0.4.8（Fetcher, impersonate=chrome）
> 探针脚本：`data/probe/probe_koubei_detail.py`　|　原始样本：`data/probe/probe_koubei_page.html`（Model Y, series_id=4363）
> 用途：补齐 `PROJECT-MEMORY/03` 标注的三个「待补」字段——口碑评分 `score`、级别 `segment`、续航/动力，并产出 RAG 评论语料。

---

## 关键发现：数据不在独立 JSON 接口，而在「口碑页」的内嵌 SSR JSON

懂车帝是 **Next.js SSR** 站点。先试了一批候选 JSON 接口（`/motor/pc/car/series/series_all_score`、`/motor/pc/koubei/list` 等共 11 个）——**全部 404**（见 `_probe_koubei_report.json`）。
但**口碑/评分页本身** `GET https://www.dongchedi.com/auto/series/score/{series_id}` 返回 200，整页 HTML 里有一段：

```html
<script id="__NEXT_DATA__" type="application/json">{ ... 整页数据 ... }</script>
```

解析这段 JSON 的 `props.pageProps`，**一个页面就同时拿到了评分 + 级别 + 续航 + 评论文本**，免登录、带 `Referer: https://www.dongchedi.com/` 即可。**单数据源懂车帝，不引汽车之家。**

- **采集入口**：`GET https://www.dongchedi.com/auto/series/score/{series_id}`（按车系遍历，series_id 取自已入库的 `dim_series`）
- **解析**：正则取出 `__NEXT_DATA__` → `json.loads` → `props.pageProps`

## 字段清单（`props.pageProps` 下，实测 Model Y）

### ① 口碑评分（去向 `fact_review`）— 在 `seriesHomeHead` / `scoreSimpleInfo`

| 字段路径 | 类型 | 示例 | 含义 | 去向 |
|---|---|---|---|---|
| `seriesHomeHead.total_score` | int | 404 | **总评分×100**（即 4.04 分，满分 5） | `fact_review.score`（÷100 回填） |
| `seriesHomeHead.total_review_count` | int | 2770 | 口碑总条数 | 校验 `fact_review.review_count` |
| `seriesHomeHead.comfort_score` | int | 409 | 舒适性（×100） | （扩展，暂存原始 JSONL） |
| `…appearance / configuration / control / power / space / interiors_score` | int | 430… | 外观/配置/操控/动力/空间/内饰分项 | （扩展） |
| `seriesKoubeiHead.score_description` | str | 优秀 | 评分等级文字 | （扩展） |

> **量纲坑**：所有 score 都是**真实分×100**（404=4.04 分）。回填 `fact_review.score`（`NUMERIC(3,1)`）时要 **÷100 并四舍五入到 1 位**。这与销量接口里恒为 0 的假 score 完全不同。

### ② 车系详情：级别 / 动力 / 续航（去向 `dim_series`）— 在 `seriesHomeHead`

| 字段路径 | 类型 | 示例 | 含义 | 去向 |
|---|---|---|---|---|
| `seriesHomeHead.car_type` | str | 中型SUV | **车系级别 segment** | `dim_series.segment` |
| `seriesHomeHead.series_new_energy` | bool | true | 是否新能源 | 辅助判定 |
| `seriesHomeHead.pc_config.recharge_mileage` | str | 593-821km | **续航里程区间** | `dim_series.endurance_km`（新增 nullable 列） |
| `seriesHomeHead.pc_config.total_electric_power` | str | 220-331kW | 电机总功率 | （扩展，可入 endurance 旁列，本期暂存 JSONL） |
| `seriesHomeHead.pc_config.driver_form` | str | 后驱/四驱 | 驱动形式 | （扩展） |
| `seriesHomeHead.pc_config.battery_type` | str | 三元锂电池/磷酸铁锂电池 | 电池类型 | （扩展） |
| `seriesHomeHead.pc_config.acceleration_time` | str | 4.3-5.9s | 零百加速 | （扩展） |

> **powertrain 说明**：现有 `dim_series.powertrain`（纯电/插混/增程）已由销量接口的 `new_energy_type` 推断且**更干净**（标准枚举），故 powertrain **沿用现值不覆盖**；车系详情这里主要补 **segment（级别）** 和 **续航**。

### ③ 评论文本（RAG 语料）— 在 `reviewListData.review_list[]`

| 字段路径 | 类型 | 示例 | 含义 |
|---|---|---|---|
| `reviewListData.total_count` | int | 2769 | 该车系口碑总数 |
| `reviewListData.has_more` | bool | true | 是否还有更多（本页内嵌约 14 条） |
| `review_list[].content` | str | 「作为坦克300和mini车主，今年突发奇想买电车…」 | **车主点评正文（RAG 主体）** |
| `review_list[].buy_car_info` | obj | `{bought_time:"2026-02", location:"贵阳", price:"28.50万", ...}` | 购车时间/城市/价格 |
| `review_list[].car_name` | str | 长续航后轮驱动版 | 具体车款 |
| `review_list[].score_info.score` | int | 456 | 该条打分（×100） |
| `review_list[].digg_count_en` / `comment_count_en` | str | 250 / 242 | 点赞/评论数 |
| `review_list[].year` | int | 2026 | 款型年 |

> **分页**：每个口碑页内嵌**首页约 14 条**评论，`has_more=true` 但翻页需逆向 XHR 接口（易踩反爬坑）。本期**只取内嵌首页**作语料**候选**（约 400 车系 × ~14 条 ≈ 5000+ 条），足够 RAG 起步；全量分页留作后续扩展。
